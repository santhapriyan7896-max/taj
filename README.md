# Taj Home Caterers — website

Single-page site. No build step, no dependencies. Open `index.html` in a browser and it works.

---

## 1. Set the contact details (do this first)

Open `script.js`. Everything you need is in the `CONFIG` block at the very top:

```js
const CONFIG = {
  phoneIntl:       "910000000000",              // digits only, with country code, no "+"
  phoneDisplay:    "+91 00000 00000",           // how it reads on screen
  whatsappIntl:    "910000000000",              // usually the same number
  whatsappMessage: "Hi Taj Home Caterers! ...", // pre-typed for the customer
  email:           "hello@tajhomecaterers.com",
  address:         "[Add your address here]",
  instagram:       "https://instagram.com/tajhomecaterers",
  formEndpoint:    ""                           // see section 4
};
```

Change these once and they update across the top bar, hero, contact section, footer and the sticky mobile bar. This is the only edit required to make the site functional.

## 2. The artwork

Every image on the site is a hand-drawn SVG — hero, all twelve gallery tiles, the social preview card and the favicon. Nothing is a placeholder, so the site is presentable as-is.

They're generated by `images/_generate.py`, once per theme:

```bash
cd images && python3 _generate.py              # both themes
cd images && python3 _generate.py terracotta   # just the live one
```

The live terracotta artwork goes to `images/`; the forest set is kept in `images/forest/`. Compositions are shared — edit a `g_*` function and it changes in every theme at once. Only the palette differs, except the banana leaf, which stays green everywhere for obvious reasons.

**Swapping in real photographs.** Drop your files into `images/` and change the `src` in `index.html`. Recommended sizes:

| Slot | Suggested size |
|---|---|
| `hero` | 2000 × 1200, landscape |
| `gallery-01` … `gallery-12` | ~1200 × 900 (02 and 08 are portrait, 05 is wide) |
| `og-image` | 1200 × 630 |
| `favicon` | 512 × 512 |

Keep each tile's `data-cat` attribute (`kitty`, `wedding`, `corporate`, `live`, `sweets`) accurate so the filter buttons keep working, and update the `<figcaption>` to describe the real event.

Photos that work: overhead shots of a full spread, live counters with a chef mid-action, guests being served, a close-up of one dish plated well. Once you have real photographs you can delete `_generate.py` and the SVGs.

## 3. The feast section

"The Feast" lays a full meal out on a banana leaf, with a toggle between two spreads:

- **Vegetarian** — the classic sadhya, 12 dishes
- **Non-vegetarian** — Chettinad style, 13 dishes: fish fry, chicken 65, egg roast, prawn roast along the top, then meen kuzhambu, chicken Chettinad and mutton curry with the rice

Static, no scroll animation. Switching redraws the leaf and the dish list underneath together.

Both come from one object, `FEASTS`, in `script.js`:

```js
const FEASTS = {
  veg: {
    label: "Vegetarian",
    note: "Shown under the heading",
    dishes: [
      { name: "Sambar",
        note: "Poured over the rice, second course",
        x: 63, y: 63,     // position on the leaf, as a % of the viewBox
        size: 130,        // relative size
        art: () => `<ellipse .../>` }   // drawn in a 120 x 120 box
    ]
  },
  nonveg: { ... }
};
```

**Adding a third feast** (Jain, festival, wedding buffet…) needs no markup change — add another key to `FEASTS` and the toggle button builds itself.

**Drawing helpers**, all authored in the same 120 x 120 box:

| Helper | Draws |
|---|---|
| `dip(colour, extra)` | a curry in a small bowl |
| `heap(colour, seed, r)` | a mound — rice, poriyal, thoran |
| `chunks(colour, seed, n)` | dry fried pieces — chicken 65, chukka |
| `fishFry()` | a whole fried fish |
| `prawns()` | three curled prawns |
| `eggRoast()` | halved boiled eggs in masala |

**How it renders.** Each dish is an SVG `<g>` inside the leaf's own `<svg>`, positioned in viewBox units — no CSS positioning or percentage sizing — so dishes scale with the leaf and stay aligned at any size.

Two gotchas if you edit the art:

- the reset sets `fill:none; stroke:currentColor` on every `<svg>`, so shapes need an explicit `fill`, and `.dish * { stroke:none }` clears the inherited stroke
- draw around the centre at `60,60`

Under 760px the on-leaf labels hide and the dish list carries the names.

## 4. Make the enquiry form deliver

Out of the box, submitting the form opens WhatsApp with every field pre-filled. That works with zero setup.

For enquiries to arrive by email instead:

1. Sign up at [formspree.io](https://formspree.io) (free tier is enough).
2. Create a form, copy the endpoint URL.
3. Paste it into `formEndpoint` in `script.js`.

If sending ever fails, the form falls back to WhatsApp and shows the phone number.

## 5. Replace the placeholder copy

Search `index.html` for:

- `[Customer Name]` — real reviews. The single most persuasive thing on the page.
- `[Add your address here]` — also update the JSON-LD block at the bottom of `index.html`
- `Serving your city & nearby areas` in the top bar
- The hero stats (16 years, 500+ events, 1000+ guests) — make sure they're true

**On pricing:** the site deliberately quotes no per-head figure, and the Menus section and FAQ both explain why — a rate that's honest at 40 guests isn't honest at 600. This also stops competitors from undercutting a published number, and gets people to message you rather than self-disqualify. If you'd rather show a "starting from" figure, add it to the `.mc-tag` line in each menu card.

## 6. Brand identity

### The arch

The name already points at a building, so the brand takes its one repeatable shape from it — an ogee arch. It appears in exactly three places, which is what makes it read as a mark rather than decoration:

- the **monogram** in the header and footer
- a **ghosted watermark** behind the hero headline
- a small **ornament** capping each menu card

The path lives in two places: `ARCH_OUTER` / `ARCH_INNER` in `images/_generate.py` for artwork, and inline SVG in `index.html` for the page. Change one and change the other.

### Type — three tiers, each with one job

| Tier | Face | Used for |
|---|---|---|
| `--display` | **Cinzel** | Headlines, the monogram, numerals. Always caps with open tracking. |
| `--serif` | **Cormorant Garamond** | Pull quotes, FAQ questions, italic accents. |
| `--sans` | **Jost** | Body copy, labels, buttons. |

Cinzel is drawn from Roman imperial inscriptions — letters made to be carved. It's a display face, not a reading face, so the rule is: **short carved phrases only.** Anything a person reads as a sentence goes in the serif or sans tier. That's why FAQ questions and pull quotes aren't in caps.

Because Cinzel runs wide and short, it has its own tokens rather than per-element overrides:

```css
--d-case:uppercase;   --d-track:.07em;
--d-weight:600;       --d-scale:.80;   /* pulls headings back */
--d-line:1.22;
```

Swapping the whole identity to another display face is one line — change `--display` and adjust `--d-scale` and `--d-track` to suit. `font-preview.html` in this folder lets you compare five directions live; delete it once you're settled.

### Colour

**Theme** sets the raw palette; the site ships in **Saffron & Terracotta**, set by `data-theme="terracotta"` on `<html>`. **Forest & Gold** is kept in `styles.css` as an alternative — remove the attribute to fall back to it, and swap `images/forest/` into `images/`.

**Tone** sets how a section uses that palette. Every section carries `tone-cream`, `tone-ivory`, `tone-deep` or `tone-accent`, each rebinding the same semantic roles — `--surface`, `--panel`, `--text`, `--heading`, `--accent`, `--rule`. Components read only those roles, never raw colours.

Sections cycle so the palette spreads evenly rather than pooling:

```
hero → cream → deep → ivory → cream → deep → ivory → cream → ivory → accent → footer
```

### The header

Top bar and nav share one solid surface (`--header-bg`) and don't change colour or opacity on scroll — only a shadow appears. To go light, change the four `--header-*` values:

```css
--header-bg:var(--ivory);      --header-text:var(--ink);
--header-soft:var(--ink-soft); --header-accent:var(--gold-700);
```

Contrast is checked across the palette — body, heading, nav, accent and button text all meet WCAG AA, secondary text clears AA-large.

## 7. How it adapts to any screen

The layout is **intrinsic** rather than breakpoint-driven. Sizes are expressed as ranges, so the site fits continuously between sizes instead of snapping at a few widths.

**The four mechanisms**

1. **Fluid root** — `html { font-size: clamp(14.6px, 0.34vw + 13.5px, 16px) }`. Everything sized in `rem` scales from that one value, so type, spacing and controls tighten together on small screens.
2. **Ranged sizing** — headings, section padding, gaps and gallery rows all use `clamp()`, so they interpolate instead of jumping.
3. **Self-arranging grids** — every multi-column grid uses `repeat(auto-fit, minmax(min(Npx, 100%), 1fr))`. Columns reflow on their own, and the `min(Npx, 100%)` is what stops a grid forcing itself wider than a narrow screen.
4. **Intrinsic media** — the leaf is an SVG with a viewBox, so it and its dishes scale as one unit at any size.

**Breakpoints only change layout, never scale:**

| Query | What changes |
|---|---|
| `1000px` | Contact and quote band go single column; footer to two columns |
| `860px` | Nav collapses to a menu; sticky WhatsApp/Call bar appears |
| `760px` | On-leaf dish labels hide; the dish key carries the names |
| `560px` | Form fields stack; gallery to two columns; footer to one |
| `380px` | Gallery to one column; buttons allowed to wrap; wider gutters |
| `520px` tall, landscape | Hero drops its minimum height; scroll hint hides |
| `1600px` | Container caps so lines don't run too long |
| `hover: none` | Hover lifts removed; 44px minimum tap targets |

Heights use `svh`, not `vh`, so mobile browser chrome doesn't create phantom scroll.

**Checking it.** Open `responsive-check.html` — it loads the real site in thirteen frames from a 320px folded phone to a 2560px ultrawide, including landscape and square ratios, each with a live self-test badge. Add any custom width to test something not listed. Delete this file when you no longer need it.

## 8. Put it online

Any static host works:

- **Netlify** — drag the `taj-caterers` folder onto [app.netlify.com/drop](https://app.netlify.com/drop). Live in seconds.
- **Vercel** — import the folder, deploy.
- **GitHub Pages** — push the folder, enable Pages in repo settings.

Then point a domain at it and update `canonical`, `og:url` and the JSON-LD `url` in `index.html`.

## 9. Getting more customers out of it

Once live, in rough order of impact:

1. **Google Business Profile** — free, and it's where most local catering searches start. Add the website link, post photos weekly, ask happy customers for reviews.
2. **Instagram bio link** — the profile has 2,479 followers and no website link. Fastest win available.
3. **Real reviews on the page** — three specific, named reviews beat any amount of design.
4. **WhatsApp everywhere** — already wired up; it converts far better than a form for this business.
5. **A photo after every event** — a gallery that visibly grows signals an active business.
